## Introduction

This document explains how the OctAttoo Flutter application should be structured following strict **Model-View-ViewModel (MVVM)** architecture, aligned with **Serverpod best practices**. This architecture uses **only built-in Flutter features** and integrates seamlessly with **Serverpod backend**.

> **Compatibility Note**: This guide is compatible with **Serverpod 2.1+ and 3.x**. Serverpod 3.0 (released December 2025) includes breaking changes in authentication and requires Dart 3.8.0+ and Flutter 3.32.0+. See [Serverpod 3.0 Upgrade Guide](https://docs.serverpod.dev/next/upgrading/upgrade-to-three) for migration details.

### Why MVVM for Flutter + Serverpod?

- **Separation of Concerns**: UI logic is separated from business logic
- **Testability**: ViewModels can be unit tested without the UI
- **Reusability**: ViewModels can be shared across different Views
- **Maintainability**: Changes to UI don't affect business logic and vice versa
- **Scalability**: Easy to add new features without breaking existing code
- **Serverpod Alignment**: Matches Serverpod's layered approach (Presentation → Business Logic → Data)

### Technologies

This architecture uses **ONLY** what's already in the project:
- ✅ Built-in Flutter (`ChangeNotifier`, `InheritedNotifier`, `StatefulWidget`, `ValueListenable`)
- ✅ Serverpod client (`octattoo_client`) - acts as the Data Layer
- ✅ `serverpod_auth_idp_flutter` for authentication
- ✅ `go_router` for navigation
- ❌ NO external state management packages (Provider, Riverpod, Bloc, etc.)
- ❌ NO dependency injection frameworks (get_it, injectable, etc.)

## MVVM Overview

### The MVVM Pattern with Serverpod

```
┌──────────────┐         ┌──────────────────┐         ┌─────────────────────┐
│     View     │ ◄────── │   ViewModel      │ ◄────── │   Model (Data)      │
│    (UI)      │         │(Business Logic)  │         │                     │
└──────────────┘         └──────────────────┘         └─────────────────────┘
      │                          │                              │
      │                          │                              │
 StatefulWidget           ChangeNotifier                 Repository Layer
 InheritedNotifier        State Management                      │
 Widgets                  Validation                            │
 ListenableBuilder        Commands                              ▼
                                                      ┌─────────────────────┐
                                                      │  Serverpod Client   │
                                                      │  (Generated Code)   │
                                                      └─────────────────────┘
                                                               │
                                                               ▼
                                                      ┌─────────────────────┐
                                                      │  Serverpod Server   │
                                                      │    (Backend)        │
                                                      └─────────────────────┘
```

### Key Principles

1. **View** knows about **ViewModel**, but not **Model** or **Serverpod Client**
2. **ViewModel** knows about **Repository**, but not **View** or **Serverpod Client**
3. **Repository** wraps **Serverpod Client** and abstracts data access
4. **Model** classes are generated by Serverpod from `.spy.yaml` files
5. Communication flows: View → ViewModel → Repository → Serverpod Client → Server
6. Data flows back: Server → Client → Repository → ViewModel → View (via `notifyListeners()`)

## Serverpod's Architectural Guidance

According to Serverpod documentation:

### Recommended Layered Approach

Serverpod encourages a **three-layer architecture**:

1. **Presentation Layer**: Flutter UI widgets
2. **Business Logic Layer**: Application's business rules (ViewModels in MVVM)
3. **Data Layer**: Serverpod client acts as the data access layer

### Repository Pattern: A Best Practice for Serverpod Apps

**While Serverpod provides direct ORM access, wrapping client methods in repository classes offers:**

- ✅ **Separation of Concerns**: Abstracts data source from business logic
- ✅ **Testability**: Enables mocking repositories instead of the Serverpod client
- ✅ **Flexibility**: Easy to change data sources without affecting business logic

> **Note**: Serverpod's ORM allows direct database access through generated model classes (e.g., `Customer.db.find()`). The repository pattern is a general software architecture best practice, not a specific Serverpod requirement, but it aligns well with clean architecture principles.

**Best Practice**:
```dart
// ❌ DON'T: Use Serverpod client directly in ViewModel
class CustomersViewModel extends ChangeNotifier {
  Future<void> load() async {
    final customers = await ServerpodClientService().client.customers.getAll();
  }
}

// ✅ DO: Use Repository to wrap Serverpod client
class CustomersViewModel extends ChangeNotifier {
  CustomersViewModel(this._repository);
  final CustomerRepository _repository;

  Future<void> load() async {
    final customers = await _repository.getAllCustomers();
  }
}
```

### State Management Freedom

Serverpod **does not mandate** any specific state management solution. You can use:
- Built-in Flutter (ChangeNotifier) ← **Our choice**
- Provider
- Riverpod
- Bloc
- GetX
- MobX
- Any other solution

For authentication state, Serverpod provides `client.auth.authInfoListenable` (a `ValueListenable<AuthSuccess?>`), which integrates with any state management solution.

## The Three Layers

### 1. Model Layer (Data)

**Purpose**: Represents the data and business domain of the application.

**Components**:
- **Data Classes**: Generated by Serverpod from `.spy.yaml` files
- **Repositories**: Wrap Serverpod client and provide clean API (Serverpod-recommended pattern)
- **Serverpod Client**: Auto-generated client that communicates with backend

**Responsibilities**:
- API communication via Serverpod client
- Custom exception handling
- Client-side caching (optional - using sqflite, Hive, or shared_preferences)
- Data validation

**What Serverpod Generates** (via `serverpod generate`):
- Model classes with `toJson()`, `fromJson()`, `copyWith()` methods
- Client-side API that mirrors server endpoint methods
- Serializable custom exceptions

**Example Structure**:
```
lib/
  src/
    data/
      models/                    # Serverpod-generated models (from .spy.yaml)
        customer.dart            # Generated: class Customer with serialization
        project.dart
        appointment.dart
      repositories/              # YOU create these (Serverpod recommendation)
        customer_repository.dart # Wraps client.customers.* methods
        project_repository.dart
        appointment_repository.dart
      exceptions/
        repository_exceptions.dart
```

### 2. ViewModel Layer (Business Logic)

**Purpose**: Manages the state and business logic for Views. Acts as a bridge between Model and View.

**Components**:
- **ChangeNotifiers**: Extends `ChangeNotifier` for reactive state management
- **Business Logic**: Contains all UI-related business logic
- **State Management**: Manages loading, error, and success states
- **Validation**: Input validation and error messages
- **Stream Handling**: Manages real-time Serverpod streams (for real-time features)

**Responsibilities**:
- Fetch data via repositories (NOT directly from Serverpod client)
- Transform data for display
- Handle user interactions
- Manage view state (loading, error, success)
- Form validation
- Subscribe to Serverpod streams for real-time updates
- Expose methods that Views can call

**Example Structure**:
```
lib/
  src/
    presentation/
      viewmodels/
        customers/
          customers_viewmodel.dart
          customers_provider.dart      # InheritedNotifier wrapper
          customer_details_viewmodel.dart
          add_customer_viewmodel.dart
        projects/
          projects_viewmodel.dart
          projects_provider.dart
```

### 3. View Layer (Presentation)

**Purpose**: Displays UI and captures user input. Should be as "dumb" as possible.

**Components**:
- **Screens**: Full-page widgets with `StatefulWidget` or `StatelessWidget`
- **Widgets**: Reusable UI components
- **InheritedNotifier**: Provides ViewModel to widget tree
- **ListenableBuilder**: Rebuilds UI when ViewModel notifies changes

**Responsibilities**:
- Display data provided by ViewModel
- Capture user input and pass to ViewModel
- Navigate based on ViewModel state
- Show loading indicators, errors, dialogs
- **NO business logic**
- **NO direct repository or Serverpod client access**

**Example Structure**:
```
lib/
  src/
    presentation/
      screens/
        customers/
          customers_screen.dart
          customer_details_screen.dart
          add_customer_screen.dart
      widgets/
        customer_card.dart
        customer_list_item.dart
```

### Example 1: Customers Feature (Complete MVVM with Serverpod)

#### Step 1: Server-Side Setup (Do This First)

**server/lib/src/endpoints/customers_endpoint.dart**
```dart
import 'package:serverpod/serverpod.dart';
import '../protocol/customer.dart';

class CustomersEndpoint extends Endpoint {
  /// Get all customers
  Future<List<Customer>> getAll(Session session) async {
    return await Customer.db.find(session);
  }

  /// Get customer by ID
  Future<Customer?> getById(Session session, int id) async {
    return await Customer.db.findById(session, id);
  }

  /// Create a new customer
  Future<Customer> create(
    Session session, {
    required String name,
    required String email,
    required String phone,
    String? notes,
  }) async {
    // Validation
    if (name.length < 2) {
      throw ValidationException(
        message: 'Name must be at least 2 characters',
        field: 'name',
      );
    }

    if (!_isValidEmail(email)) {
      throw ValidationException(
        message: 'Invalid email format',
        field: 'email',
      );
    }

    final customer = Customer(
      name: name,
      email: email,
      phone: phone,
      notes: notes,
      createdAt: DateTime.now(),
    );

    return await Customer.db.insertRow(session, customer);
  }

  /// Update customer
  Future<Customer> update(Session session, Customer customer) async {
    return await Customer.db.updateRow(session, customer);
  }

  /// Delete customer
  Future<void> delete(Session session, int id) async {
    await Customer.db.deleteRow(session, id);
  }

  bool _isValidEmail(String email) {
    return RegExp(r'^[\w-\.]+@([\w-]+\.)+[\w-]{2,4}$').hasMatch(email);
  }
}
```

#### Step 2: Model Layer (Client-Side)

**lib/src/data/repositories/customer_repository.dart**
```dart
import 'package:octattoo_client/octattoo_client.dart';
import 'package:octattoo_flutter/core/serverpod_client_service.dart';

/// Repository for Customer data access
/// Wraps Serverpod client (Serverpod-recommended pattern)
class CustomerRepository {
  CustomerRepository._();
  static final CustomerRepository instance = CustomerRepository._();

  /// Access to Serverpod client
  Client get _client => ServerpodClientService().client;

  /// Get all customers
  Future<List<Customer>> getAllCustomers() async {
    try {
      // Calls the generated client method which calls CustomersEndpoint.getAll()
      return await _client.customers.getAll();
    } on ValidationException catch (e) {
      // Handle Serverpod custom exception
      throw RepositoryException('Validation error: ${e.message}');
    } on ServerpodException catch (e) {
      // Handle generic Serverpod exception
      throw RepositoryException('Failed to fetch customers: ${e.message}');
    } catch (e) {
      throw RepositoryException('Unexpected error: $e');
    }
  }

  /// Get customer by ID
  Future<Customer?> getCustomerById(int id) async {
    try {
      return await _client.customers.getById(id);
    } on ServerpodException catch (e) {
      throw RepositoryException('Failed to fetch customer: ${e.message}');
    } catch (e) {
      throw RepositoryException('Unexpected error: $e');
    }
  }

  /// Create a new customer
  Future<Customer> createCustomer({
    required String name,
    required String email,
    required String phone,
    String? notes,
  }) async {
    try {
      return await _client.customers.create(
        name: name,
        email: email,
        phone: phone,
        notes: notes,
      );
    } on ValidationException catch (e) {
      // Propagate validation errors to ViewModel with field information
      throw ValidationRepositoryException(
        message: e.message,
        field: e.field,
      );
    } on ServerpodException catch (e) {
      throw RepositoryException('Failed to create customer: ${e.message}');
    } catch (e) {
      throw RepositoryException('Unexpected error: $e');
    }
  }

  /// Update existing customer
  Future<Customer> updateCustomer(Customer customer) async {
    try {
      return await _client.customers.update(customer);
    } on ValidationException catch (e) {
      throw ValidationRepositoryException(
        message: e.message,
        field: e.field,
      );
    } on ServerpodException catch (e) {
      throw RepositoryException('Failed to update customer: ${e.message}');
    } catch (e) {
      throw RepositoryException('Unexpected error: $e');
    }
  }

  /// Delete customer
  Future<void> deleteCustomer(int id) async {
    try {
      await _client.customers.delete(id);
    } on ServerpodException catch (e) {
      throw RepositoryException('Failed to delete customer: ${e.message}');
    } catch (e) {
      throw RepositoryException('Unexpected error: $e');
    }
  }
}

/// Custom exception for repository errors
class RepositoryException implements Exception {
  RepositoryException(this.message);
  final String message;

  @override
  String toString() => message;
}

/// Validation-specific exception with field information
class ValidationRepositoryException extends RepositoryException {
  ValidationRepositoryException({
    required String message,
    required this.field,
  }) : super(message);

  final String field;
}
```

#### Step 3: ViewModel Layer

**lib/src/presentation/viewmodels/customers/customers_viewmodel.dart**
```dart
import 'package:flutter/foundation.dart';
import 'package:octattoo_client/octattoo_client.dart';
import '../../../data/repositories/customer_repository.dart';

/// ViewModel for the Customers list screen
/// Manages state, business logic, and data for the View
class CustomersViewModel extends ChangeNotifier {
  CustomersViewModel(this._repository);

  final CustomerRepository _repository;

  // State
  List<Customer> _customers = [];
  bool _isLoading = false;
  String? _errorMessage;
  String _searchQuery = '';

  // Getters (Expose state to View)
  List<Customer> get customers => _searchQuery.isEmpty
      ? _customers
      : _customers
          .where((c) =>
              c.name.toLowerCase().contains(_searchQuery.toLowerCase()) ||
              c.email.toLowerCase().contains(_searchQuery.toLowerCase()))
          .toList();

  bool get isLoading => _isLoading;
  String? get errorMessage => _errorMessage;
  bool get hasError => _errorMessage != null;
  bool get isEmpty => _customers.isEmpty && !_isLoading;
  int get customerCount => _customers.length;

  // Commands (Methods that View can call)

  /// Initialize: load customers from repository
  Future<void> initialize() async {
    await loadCustomers();
  }

  /// Load all customers from repository
  Future<void> loadCustomers() async {
    _isLoading = true;
    _errorMessage = null;
    notifyListeners();

    try {
      _customers = await _repository.getAllCustomers();
      _errorMessage = null;
    } on RepositoryException catch (e) {
      _errorMessage = e.message;
      _customers = [];
    } catch (e) {
      _errorMessage = 'An unexpected error occurred';
      _customers = [];
    } finally {
      _isLoading = false;
      notifyListeners();
    }
  }

  /// Refresh customer list
  Future<void> refresh() async {
    await loadCustomers();
  }

  /// Update search query and filter customers
  void updateSearchQuery(String query) {
    _searchQuery = query;
    notifyListeners();
  }

  /// Delete a customer
  Future<bool> deleteCustomer(int customerId) async {
    try {
      await _repository.deleteCustomer(customerId);
      _customers.removeWhere((c) => c.id == customerId);
      notifyListeners();
      return true;
    } on RepositoryException catch (e) {
      _errorMessage = e.message;
      notifyListeners();
      return false;
    } catch (e) {
      _errorMessage = 'Failed to delete customer';
      notifyListeners();
      return false;
    }
  }

  /// Clear error message
  void clearError() {
    _errorMessage = null;
    notifyListeners();
  }
}
```

```dart
import 'package:flutter/material.dart';
import 'customers_viewmodel.dart';
import '../../../data/repositories/customer_repository.dart';

/// InheritedNotifier wrapper for CustomersViewModel
/// Pattern: Same as AppSettingsProvider
class _CustomersInherited extends InheritedNotifier<CustomersViewModel> {
  const _CustomersInherited({
    required CustomersViewModel notifier,
    required super.child,
  }) : super(notifier: notifier);
}

/// Provides CustomersViewModel to widget tree
class CustomersProvider extends StatefulWidget {
  const CustomersProvider({
    super.key,
    required this.child,
  });

  final Widget child;

  /// Access ViewModel with automatic rebuilds
  static CustomersViewModel of(BuildContext context) {
    final inherited =
        context.dependOnInheritedWidgetOfExactType<_CustomersInherited>();
    assert(
      inherited?.notifier != null,
      'No CustomersProvider found in context',
    );
    return inherited!.notifier!;
  }

  /// Access ViewModel without rebuilds (for callbacks)
  static CustomersViewModel read(BuildContext context) {
    final inherited =
        context.getInheritedWidgetOfExactType<_CustomersInherited>();
    assert(
      inherited?.notifier != null,
      'No CustomersProvider found in context',
    );
    return inherited!.notifier!;
  }

  @override
  State<CustomersProvider> createState() => _CustomersProviderState();
}

class _CustomersProviderState extends State<CustomersProvider> {
  late final CustomersViewModel _viewModel;

  @override
  void initState() {
    super.initState();
    _viewModel = CustomersViewModel(CustomerRepository.instance);
    _viewModel.initialize();
  }

  @override
  void dispose() {
    _viewModel.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return _CustomersInherited(
      notifier: _viewModel,
      child: widget.child,
    );
  }
}
```

```dart
import 'package:flutter/foundation.dart';
import 'package:octattoo_client/octattoo_client.dart';
import '../../../data/repositories/customer_repository.dart';

/// ViewModel for adding a new customer
/// Handles form validation and submission
class AddCustomerViewModel extends ChangeNotifier {
  AddCustomerViewModel(this._repository);

  final CustomerRepository _repository;

  // Form state
  String _name = '';
  String _email = '';
  String _phone = '';
  String _notes = '';

  // Validation errors (can come from server-side ValidationException)
  String? _nameError;
  String? _emailError;
  String? _phoneError;

  // Submission state
  bool _isSubmitting = false;
  String? _errorMessage;

  // Getters
  String get name => _name;
  String get email => _email;
  String get phone => _phone;
  String get notes => _notes;

  String? get nameError => _nameError;
  String? get emailError => _emailError;
  String? get phoneError => _phoneError;

  bool get isSubmitting => _isSubmitting;
  String? get errorMessage => _errorMessage;
  bool get isValid =>
      _nameError == null &&
      _emailError == null &&
      _phoneError == null &&
      _name.isNotEmpty &&
      _email.isNotEmpty &&
      _phone.isNotEmpty;

  // Commands

  void updateName(String value) {
    _name = value;
    _validateName();
    notifyListeners();
  }

  void updateEmail(String value) {
    _email = value;
    _validateEmail();
    notifyListeners();
  }

  void updatePhone(String value) {
    _phone = value;
    _validatePhone();
    notifyListeners();
  }

  void updateNotes(String value) {
    _notes = value;
    notifyListeners();
  }

  // Client-side validation (for instant feedback)
  void _validateName() {
    if (_name.isEmpty) {
      _nameError = 'Name is required';
    } else if (_name.length < 2) {
      _nameError = 'Name must be at least 2 characters';
    } else {
      _nameError = null;
    }
  }

  void _validateEmail() {
    if (_email.isEmpty) {
      _emailError = 'Email is required';
    } else if (!_isValidEmail(_email)) {
      _emailError = 'Please enter a valid email';
    } else {
      _emailError = null;
    }
  }

  void _validatePhone() {
    if (_phone.isEmpty) {
      _phoneError = 'Phone is required';
    } else if (_phone.length < 10) {
      _phoneError = 'Please enter a valid phone number';
    } else {
      _phoneError = null;
    }
  }

  bool _isValidEmail(String email) {
    return RegExp(r'^[\w-\.]+@([\w-]+\.)+[\w-]{2,4}$').hasMatch(email);
  }

  /// Submit the form and create customer
  /// Server-side validation will also run and may throw ValidationException
  Future<Customer?> submit() async {
    // Client-side validation first
    _validateName();
    _validateEmail();
    _validatePhone();

    if (!isValid) {
      notifyListeners();
      return null;
    }

    _isSubmitting = true;
    _errorMessage = null;
    notifyListeners();

    try {
      final customer = await _repository.createCustomer(
        name: _name,
        email: _email,
        phone: _phone,
        notes: _notes.isEmpty ? null : _notes,
      );

      _isSubmitting = false;
      notifyListeners();
      return customer;
    } on ValidationRepositoryException catch (e) {
      // Handle server-side validation errors
      // Set the error on the specific field
      switch (e.field) {
        case 'name':
          _nameError = e.message;
          break;
        case 'email':
          _emailError = e.message;
          break;
        case 'phone':
          _phoneError = e.message;
          break;
        default:
          _errorMessage = e.message;
      }
      _isSubmitting = false;
      notifyListeners();
      return null;
    } on RepositoryException catch (e) {
      _errorMessage = e.message;
      _isSubmitting = false;
      notifyListeners();
      return null;
    } catch (e) {
      _errorMessage = 'An unexpected error occurred';
      _isSubmitting = false;
      notifyListeners();
      return null;
    }
  }

  /// Reset form
  void reset() {
    _name = '';
    _email = '';
    _phone = '';
    _notes = '';
    _nameError = null;
    _emailError = null;
    _phoneError = null;
    _errorMessage = null;
    notifyListeners();
  }
}
```

## State Management

### Built-in Flutter: ChangeNotifier + InheritedNotifier

This project uses **only built-in Flutter state management**, following the pattern established in `AppSettingsNotifier` and `AppSettingsProvider`.

#### The Pattern

```dart
// 1. ViewModel extends ChangeNotifier
class MyViewModel extends ChangeNotifier {
  int _counter = 0;
  int get counter => _counter;

  void increment() {
    _counter++;
    notifyListeners(); // Notifies all listeners
  }
}

// 2. InheritedNotifier provides ViewModel
class _MyInherited extends InheritedNotifier<MyViewModel> {
  const _MyInherited({
    required MyViewModel notifier,
    required super.child,
  }) : super(notifier: notifier);
}

// 3. Stateful wrapper manages lifecycle
class MyProvider extends StatefulWidget {
  const MyProvider({super.key, required this.child});
  final Widget child;

  static MyViewModel of(BuildContext context) {
    final inherited = context.dependOnInheritedWidgetOfExactType<_MyInherited>();
    return inherited!.notifier!;
  }

  @override
  State<MyProvider> createState() => _MyProviderState();
}

class _MyProviderState extends State<MyProvider> {
  late final MyViewModel _viewModel;

  @override
  void initState() {
    super.initState();
    _viewModel = MyViewModel();
  }

  @override
  void dispose() {
    _viewModel.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return _MyInherited(notifier: _viewModel, child: widget.child);
  }
}
```

### When to Rebuild vs When Not To

```dart
// Use .of() when you WANT rebuilds (in build method)
final viewModel = MyProvider.of(context);
Text('Counter: ${viewModel.counter}'); // Rebuilds when counter changes

// Use .read() when you DON'T want rebuilds (in callbacks)
final viewModel = MyProvider.read(context);
onPressed: () => viewModel.increment(); // No rebuild needed here
```

## Authentication State Management

### Using Serverpod's authInfoListenable

Serverpod provides `client.auth.authInfoListenable`, which is a `ValueListenable<AuthSuccess?>` that can be used for listening to authentication state changes. This is perfect for managing authentication state in MVVM.

> **Verified**: According to [Serverpod's official documentation](https://docs.serverpod.dev/concepts/authentication/basics), "The authInfoListenable property provides a ValueListenable<AuthSuccess?> to be used for listening to changes."

```dart
/// ViewModel for authentication state
/// Wraps Serverpod's authInfoListenable
class AuthViewModel extends ChangeNotifier {
  AuthViewModel() {
    // Listen to Serverpod's auth state changes
    _client.auth.authInfoListenable.addListener(_onAuthStateChanged);
  }

  final _client = ServerpodClientService().client;

  // State
  AuthSuccess? _authInfo;
  bool _isLoading = false;
  String? _errorMessage;

  // Getters
  bool get isAuthenticated => _client.auth.isAuthenticated;
  AuthSuccess? get authInfo => _authInfo ?? _client.auth.authInfo;
  String? get userEmail => authInfo?.userIdentifier;
  bool get isLoading => _isLoading;
  String? get errorMessage => _errorMessage;
  bool get hasError => _errorMessage != null;

  // Commands

  /// Sign in with email/password
  Future<bool> signIn({
    required String email,
    required String password,
  }) async {
    _isLoading = true;
    _errorMessage = null;
    notifyListeners();

    try {
      final authSuccess = await _client.emailIdp.login(
        email: email,
        password: password,
      );
      _authInfo = authSuccess;
      _isLoading = false;
      notifyListeners();
      return true;
    } on EmailAccountLoginException catch (e) {
      _isLoading = false;
      switch (e.reason) {
        case EmailAccountLoginExceptionReason.invalidCredentials:
          _errorMessage = 'Invalid email or password';
          break;
        case EmailAccountLoginExceptionReason.tooManyAttempts:
          _errorMessage = 'Too many login attempts. Please try again later.';
          break;
        default:
          _errorMessage = 'Login failed';
      }
      notifyListeners();
      return false;
    } catch (e) {
      _isLoading = false;
      _errorMessage = 'An unexpected error occurred';
      notifyListeners();
      return false;
    }
  }

  /// Sign out
  Future<void> signOut() async {
    await _client.auth.signOut();
    _authInfo = null;
    notifyListeners();
  }

  /// Listener for auth state changes
  void _onAuthStateChanged() {
    _authInfo = _client.auth.authInfo;
    notifyListeners();
  }

  @override
  void dispose() {
    _client.auth.authInfoListenable.removeListener(_onAuthStateChanged);
    super.dispose();
  }
```

## Real-time Updates with Streams

Serverpod 2.1+ supports **real-time streaming via WebSockets** using **streaming methods**. This is perfect for features like live appointment updates, notifications, or collaborative editing.

> **Important**: Legacy streaming endpoints (`session.messages.createStream`) are deprecated and will be removed in a future version. Use **streaming methods** (shown below) for all new code.

```dart
class AppointmentsEndpoint extends Endpoint {

    // Send initial full data
    final appointments = await Appointment.db.find(session);
    yield AppointmentUpdate(
      type: UpdateType.initial,
      appointments: appointments,

    // For a real implementation, you might:

    // 2. Use a StreamController to manage updates
    // 3. Yield updates as they occur

    // Example: Periodic updates (replace with actual event-driven logic)
```

### Client-Side: ViewModel with Stream Handling

**lib/src/presentation/viewmodels/appointments/appointments_viewmodel.dart**
```dart
import 'dart:async';
import 'package:flutter/foundation.dart';
import 'package:octattoo_client/octattoo_client.dart';
import 'package:serverpod_flutter/serverpod_flutter.dart';
import '../../../data/repositories/appointment_repository.dart';

/// ViewModel with real-time stream support
class AppointmentsViewModel extends ChangeNotifier {
  AppointmentsViewModel(this._repository);

  final AppointmentRepository _repository;
  StreamSubscription<AppointmentUpdate>? _streamSubscription;

  // State
  List<Appointment> _appointments = [];
  bool _isLoading = false;
  bool _isStreaming = false;
  String? _errorMessage;

  // Getters
  List<Appointment> get appointments => _appointments;
  bool get isLoading => _isLoading;
  bool get isStreaming => _isStreaming;
  String? get errorMessage => _errorMessage;
  bool get hasError => _errorMessage != null;

  /// Initialize and start streaming
  Future<void> initialize() async {
    await startStreaming();
  }

  /// Start listening to real-time updates
  Future<void> startStreaming() async {
    if (_isStreaming) return;

    _isLoading = true;
    _errorMessage = null;
    notifyListeners();

    try {
      // Get the stream from repository
      final stream = await _repository.getAppointmentUpdatesStream();

      // Subscribe to stream
      _streamSubscription = stream.listen(
        _handleAppointmentUpdate,
        onError: _handleStreamError,
        onDone: _handleStreamDone,
      );

      _isStreaming = true;
      _isLoading = false;
      notifyListeners();
    } catch (e) {
      _errorMessage = 'Failed to connect to real-time updates';
      _isLoading = false;
      notifyListeners();
    }
  }

  /// Handle incoming appointment updates
  void _handleAppointmentUpdate(AppointmentUpdate update) {
    switch (update.type) {
      case UpdateType.initial:
        // Initial full data load
        _appointments = update.appointments ?? [];
        break;

      case UpdateType.created:
        // Add new appointment
        if (update.appointment != null) {
          _appointments.add(update.appointment!);
        }
        break;

      case UpdateType.updated:
        // Update existing appointment
        if (update.appointment != null) {
          final index = _appointments.indexWhere(
            (a) => a.id == update.appointment!.id,
          );
          if (index != -1) {
            _appointments[index] = update.appointment!;
          }
        }
        break;

      case UpdateType.deleted:
        // Remove deleted appointment
        if (update.appointmentId != null) {
          _appointments.removeWhere((a) => a.id == update.appointmentId);
        }
        break;
    }

    notifyListeners();
  }

  /// Handle stream errors
  void _handleStreamError(Object error) {
    if (error is MethodStreamException) {
      _errorMessage = 'Connection lost. Attempting to reconnect...';
    } else {
      _errorMessage = 'Stream error: $error';
    }
    _isStreaming = false;
    notifyListeners();

    // Attempt reconnection after 5 seconds
    Future.delayed(const Duration(seconds: 5), () {
      if (!_isStreaming) {
        startStreaming();
      }
    });
  }

  /// Handle stream completion
  void _handleStreamDone() {
    _isStreaming = false;
    notifyListeners();
  }

  /// Stop streaming
  Future<void> stopStreaming() async {
    await _streamSubscription?.cancel();
    _streamSubscription = null;
    _isStreaming = false;
    notifyListeners();
  }

  @override
  void dispose() {
    _streamSubscription?.cancel();
    super.dispose();
  }
}
```

## Client-Side Caching Strategy

Serverpod has **server-side caching** (using Redis), but **NO built-in client-side caching**. You need to implement it yourself using Flutter's local storage solutions.

### Recommended Approach

Use **sqflite**, **Hive**, or **shared_preferences** for client-side caching.

#### Example: Simple Cache with shared_preferences

**lib/src/data/cache/cache_manager.dart**
```dart
import 'dart:convert';
import 'package:shared_preferences/shared_preferences.dart';

class CacheManager {
  CacheManager._();
  static final CacheManager instance = CacheManager._();

  static const _customersCacheKey = 'customers_cache';
  static const _customersTimestampKey = 'customers_timestamp';
  static const _cacheDuration = Duration(minutes: 5);

  /// Cache customers data
  Future<void> cacheCustomers(List<Map<String, dynamic>> customers) async {
    final prefs = await SharedPreferences.getInstance();
    await prefs.setString(_customersCacheKey, jsonEncode(customers));
    await prefs.setInt(
      _customersTimestampKey,
      DateTime.now().millisecondsSinceEpoch,
    );
  }

  /// Get cached customers if not stale
  Future<List<Map<String, dynamic>>?> getCachedCustomers() async {
    final prefs = await SharedPreferences.getInstance();

    final timestamp = prefs.getInt(_customersTimestampKey);
    if (timestamp == null) return null;

    final cacheTime = DateTime.fromMillisecondsSinceEpoch(timestamp);
    final isStale = DateTime.now().difference(cacheTime) > _cacheDuration;

    if (isStale) {
      await clearCustomersCache();
      return null;
    }

    final cached = prefs.getString(_customersCacheKey);
    if (cached == null) return null;

    return List<Map<String, dynamic>>.from(jsonDecode(cached));
  }

  /// Clear customers cache
  Future<void> clearCustomersCache() async {
    final prefs = await SharedPreferences.getInstance();
    await prefs.remove(_customersCacheKey);
    await prefs.remove(_customersTimestampKey);
  }
}
```

#### Repository with Caching

**lib/src/data/repositories/customer_repository.dart**
```dart
import 'package:octattoo_client/octattoo_client.dart';
import '../cache/cache_manager.dart';

class CustomerRepository {
  static final instance = CustomerRepository._();
  CustomerRepository._();

  Client get _client => ServerpodClientService().client;
  final _cache = CacheManager.instance;

  /// Get all customers with caching
  Future<List<Customer>> getAllCustomers({bool forceRefresh = false}) async {
    try {
      // 1. Try to load from cache first (if not forcing refresh)
      if (!forceRefresh) {
        final cached = await _cache.getCachedCustomers();
        if (cached != null) {
          return cached.map((json) => Customer.fromJson(json)).toList();
        }
      }

      // 2. If cache miss or force refresh, fetch from server
      final customers = await _client.customers.getAll();

      // 3. Update cache
      await _cache.cacheCustomers(
        customers.map((c) => c.toJson()).toList(),
      );

      return customers;
    } catch (e) {
      // 4. On error, try to return stale cache
      final cached = await _cache.getCachedCustomers();
      if (cached != null) {
        return cached.map((json) => Customer.fromJson(json)).toList();
      }

      throw RepositoryException('Failed to fetch customers: $e');
    }
  }

  /// Clear cache (e.g., after create/update/delete)
  Future<void> invalidateCache() async {
    await _cache.clearCustomersCache();
  }
}
```

## Best Practices

### 1. Repository Pattern (Best Practice)

Wrap Serverpod client in repositories for better architecture:

```dart
// ❌ DON'T: Direct client access in ViewModel
class MyViewModel extends ChangeNotifier {
  Future<void> load() {
    final data = await ServerpodClientService().client.myEndpoint.getData();
  }
}

// ✅ DO: Use Repository abstraction
class MyViewModel extends ChangeNotifier {
  MyViewModel(this._repository);
  final MyRepository _repository;

  Future<void> load() {
    final data = await _repository.getData();
  }
}
```

## Summary

### Key Architectural Decisions

1. **MVVM Pattern**: Clear separation of View, ViewModel, and Model
2. **Repository Pattern**: Serverpod recommends wrapping client (for testability and flexibility)
3. **State Management**: Built-in Flutter (`ChangeNotifier` + `InheritedNotifier`)
4. **Code Generation**: Serverpod generates models and client code
5. **Authentication**: Use Serverpod's `authInfoListenable` (`ValueListenable`)
6. **Real-time**: Serverpod streaming via WebSockets
7. **Error Handling**: Custom serializable exceptions from Serverpod
8. **Caching**: Manual implementation using sqflite/Hive/shared_preferences

### The Complete Pattern

### Serverpod-Specific Best Practices

✅ **DO**:
- Run `serverpod generate --watch` during development
- Use repository pattern to wrap Serverpod client (recommended for clean architecture)
- Define custom exceptions in `.spy.yaml` for specific error handling
- Use `client.auth.authInfoListenable` (a `ValueListenable<AuthSuccess?>`) for auth state
- Implement client-side caching manually (Serverpod doesn't provide built-in client caching)
- Dispose stream subscriptions properly
- Handle `ValidationException`, `ServerpodException`, and custom exceptions
- Use streaming methods (not deprecated streaming endpoints) for real-time features

❌ **DON'T**:
- Access Serverpod client directly from ViewModels (use repositories)
- Create duplicate models (use Serverpod-generated ones)
- Forget to run `serverpod generate` after protocol changes
- Expect built-in client-side caching (you must implement it)
- Modify generated files (they'll be overwritten on next generate)
- Use legacy streaming endpoints with `session.messages.createStream` (deprecated)
